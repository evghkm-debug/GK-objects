ЗОЛОТОЙ КЛЮЧИК — ОБНОВЛЕНИЕ 0.4.1

Что уже сделано
Кнопка «Скачать все фото (...) одним ZIP» прямо в карточке объекта.
Та же возможность сохранена в «Посмотреть все фото».
В списке объектов отображается версия v0.4.1.
Сохранены существующая база objectsSurveyDB и прежние функции.
Исправлены сохранение при выходе, добавлены резервное восстановление и архив.
Код общей базы готов, но реального подключения ещё нет.

1. Сохранить данные перед обновлением
На КАЖДОМ телефоне открыть приложение обычным способом, нажать ⇩
вверху списка объектов. Сохранить objects-backup-....json.
Копия содержит объекты и фото. Не очищать данные сайта и не удалять
браузер. Данные телефона пока не находятся в GitHub или Supabase.

2. Опубликовать обновление — проще с компьютера
Скачать и распаковать этот ZIP.
Открыть https://github.com/evghkm-debug/GK-objects в своём аккаунте.
Выбрать main, затем Add file → Upload files.
Перетащить файлы из распакованной папки в корень репозитория,
сохранив вложенные папки. Не загружать сам ZIP и внешнюю папку целиком.
index.html и app.js должны оказаться в корне, vendor/jszip.min.js — в vendor.
Не удалять остальные файлы репозитория. Нажать Commit changes.
Дождаться успешного запуска pages build and deployment во вкладке Actions.
Если потребуется проверить настройки Pages: Settings → Pages;
источник должен указывать на ту ветку/папку, куда загружено приложение.
Существующий адрес сайта сохраняется:
https://evghkm-debug.github.io/GK-objects/

3. Проверить обновление на телефоне
При включённом интернете открыть прежнее приложение, обновить страницу,
закрыть и открыть снова. В списке объектов должна быть версия v0.4.1.
Если версия старая, НЕ очищать данные сайта: прислать скрин списка объектов
и результат последней публикации в Actions.
Открыть объект с фото. Нажать «Скачать все фото (...) одним ZIP».
Найти ZIP в загрузках телефона, распаковать средствами файлового менеджера.
В архиве будут снимки всех этапов этого объекта в сохранённом качестве.
Автоматическое попадание распакованных фото в системную галерею не гарантируется.

4. Разрешить дальнейшие обновления через GitHub
https://github.com/settings/installations
Найти интеграцию ChatGPT/OpenAI/Codex → Configure.
Repository access → Only select repositories → GK-objects → Save.
В Permissions проверить Contents: нужен доступ на запись.
Если доступ только на чтение и изменить его нельзя, прислать скрин:
выбор репозитория не превращает читающую интеграцию в пишущую.
На последней попытке автоматическая запись получила GitHub API 403.
Ручная публикация из пункта 2 доступна владельцу независимо от этого доступа.

5. Подключить Supabase для общей базы
Открыть https://supabase.com/dashboard и войти в свой аккаунт.
Выбрать существующий отдельный проект GK-objects или создать его,
если такого проекта нет. Пароль базы сохранить у себя.
В ChatGPT открыть Плагины → установленный Supabase, завершить
подключение внешнего аккаунта, если оно предлагается.
В окне авторизации выбрать организацию с проектом GK-objects.
Установленный плагин и подключённый аккаунт — разные состояния.
Если инструментов нет после авторизации, перезапустить ChatGPT;
для диагностики в новом чате выбрать @Supabase и попросить показать проекты.
Прислать в рабочий чат ссылку на нужный проект и результат подключения.
Пароли, service_role, sb_secret и персональные токены не присылать.

После получения доступа разработчик применит готовую схему, настроит
закрытое хранилище, вход сотрудников и публичные настройки приложения,
проверит реальный API, обновит кэш и повторно опубликует приложение.
Одной установки плагина недостаточно для синхронизации телефонов.
Техническая последовательность: supabase/SETUP.md в этом архиве.

6. Когда общая база будет подключена и проверена
На каждом телефоне открыть ☁, войти в учётную запись команды.
После резервного копирования перенести прежние локальные объекты кнопкой
«Перенести ... объектов в общую базу».
Проверить на втором телефоне объект, контакты, площади и фотографии.
Передача при открытом приложении: после изменений, при восстановлении сети,
вручную и периодически. При конфликте сохраняются обе версии для сверки.
До настройки и проверки сервера эти действия недоступны.

Проверено программно: сохранение после выхода, ZIP, восстановление,
модель обмена между двумя устройствами и правила доступа SQL.
Реальные смартфоны, камера и рабочий Supabase пока не проверены.
